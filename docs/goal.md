# 2. V1 核心业务目标

优先完成以下业务闭环：

顾客浏览商品
→ 选择款式
→ 提交量体资料
→ 店员审核并报价
→ 顾客确认报价
→ 店员安排制作
→ 店员填写发货信息
→ 顾客查看订单进度
→ 订单完成。

这是整个项目的第一优先级。

# 3. 交易规则和数据安全

不要把普通电商购物车逻辑直接套用到定制业务。

建议状态机：

- PENDING_REVIEW：待审核
- PENDING_QUOTE：待报价
- QUOTED：已报价，待顾客确认
- CONFIRMED：顾客已确认
- IN_PRODUCTION：制作中
- SHIPPED：已发货
- COMPLETED：已完成
- CANCELLED：已取消

可以根据实际实现增加拒绝、重新报价、取消申请等状态，但必须保证状态转换合法。

## 报价机制

报价至少保存：

- 商品快照。
- 量体资料快照或受控引用。
- 报价金额。
- 运费。
- 制作周期。
- 报价说明。
- 报价版本。
- 有效期（待商家确认）。
- 创建人和创建时间。

报价变更必须生成新版本。

顾客确认时，后端必须检查其确认的是否为当前有效版本。

订单确认后，不能因为后台修改商品而改变历史订单。

金额使用整数分存储。

## 支付

V1 默认不启用真实微信支付。

可以定义 PaymentGateway 接口，但使用明确禁用的适配器。禁止假支付成功、伪造已支付状态或生成虚假退款记录。

如果未来商家确认线上收款，再单独实现全款或定金规则。

当前不得索取、保存或使用真实商户支付密钥。

## 隐私

量体资料、联系方式、收货地址属于需要严格保护的数据。

- 只收集业务必要信息。
- 不将量体资料写入普通日志。
- 不在前端公开其他顾客的资料。
- 后端进行订单归属和角色权限校验。
- 不使用真实客户数据进行学校服务器测试。
- 测试数据全部使用虚构数据。
- 不允许把学校服务器作为正式生产环境。

# 6. 极其重要：资源使用预算

我对资源使用有明确限制。

## A. 本地磁盘硬限制

本地最多允许新增 10GB。

目标控制在 8GB 以内，预留至少 2GB。

开始时先记录：

- 工作区原始大小。
- 所在磁盘剩余空间。
- WSL 虚拟磁盘大小（适用时）。
- 已存在的构建缓存。
- 微信开发者工具相关项目缓存。

此后记录每个阶段新增的磁盘占用。

严禁：

- 本地 npm install 大型依赖树。
- 本地 Docker 镜像和数据库。
- 重复保存原始图片。
- 生成大量无用截图和视频。
- 无限增长的日志。
- 重复打包多个相同版本。
- 下载完整的浏览器自动化环境，除非已经存在且确有必要。

本地新增空间达到 8GB 时暂停新增资源并清理本项目明确归属的临时产物。

达到 10GB 时立即停止一切新增磁盘写入，汇报情况，等待我处理。

禁止擅自删除其他项目、系统文件和全局缓存。

## B. 学校服务器资源限制

虽然服务器拥有较高配置，但必须节制。

默认预算：

- 构建任务：最多 4 CPU 核。
- 构建内存：最多 8GB。
- 日常测试服务：总计最多 2.5 CPU 核、4GB 内存。
- 同时运行的重型任务：最多 1 个。
- 图片批处理并发：最多 2 个。
- 测试并发：最多 2 个 Worker。

项目新增磁盘使用目标不超过 8GB，达到 8GB 暂停并汇报，10GB 未经我批准不得继续扩张。

开始前必须检查：

- `df -h`
- `df -i`
- `free -h`
- `uptime`
- `docker ps`
- `docker system df`
- 当前其他项目的容器、端口和磁盘卷。

构建前、构建中、构建后均要监控资源。

Docker 必须设置容器资源限制、日志轮转和独立命名空间。

日志默认采用有限大小和有限文件数量。

禁止：

- 使用全部 128 核进行构建。
- 无限制批量处理图片。
- 同时启动多个完整构建。
- 无限增长的 Docker 日志。
- 全局清理 Docker。
- 删除其他项目的镜像、卷、容器。
- 修改学校服务器上其他项目的端口、数据库或服务。
- 运行未经批准的大规模压力测试。

如果服务器剩余磁盘不足 20%，暂停重型任务。

每次任务记录 CPU 峰值、内存峰值、磁盘增量、执行时间。

建立：

```
docs/agent/RESOURCE-LEDGER.md
```

记录本地和服务器资源使用情况。

服务器配置再强，也不能成为浪费资源的理由。
